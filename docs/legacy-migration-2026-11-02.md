# Legacy wallet migration, 2026-11-02

The seven testnet smart accounts registered before user-owned onboarding (2026-11-01) were owned by the backend demo-owner key (derived from `AGENT_SIGNER_SECRET`) and their agent pool rule had no policy, so the agent key could withdraw to any address (proven on testnet by `scripts/verify-guard.ts`).

On 2026-11-02 between 11:14 and 11:17 UTC each one got, owner-signed by the demo owner (`GDMVAPAA…DJ47`) and paid by the agent key (`GA7VW73O…NGS5W`):

1. the `vigil-guard` RiskGate on the pool rule (#1): every pool request must be the wallet's own (supplied from and withdrawn to itself), and deposits need a fresh Vigil rating ≥ 60 (at most 2 h old) from the testnet registry; withdrawals are never rating-gated;
2. the RiskGate on the USDC rule (#2): transfers may only pay the testnet pool;
3. its user as a co-owner (`Signer::Delegated(G)`) of the Default rule. With two signers and no policy, every owner change now needs the user's signature as well, so the backend can no longer change the wallet alone.

The backend key leaves a wallet when its user signs "Finalize ownership" in the app (step 4 of `scripts/migrate-legacy-accounts.ts`).

The steps are `src/lib/legacyMigration.ts`. They ran on the production deployment, which holds the key (a Sensitive Vercel variable the script cannot pull), through a one-off route that was removed afterwards. A re-run reports "nothing to do" for all seven.
